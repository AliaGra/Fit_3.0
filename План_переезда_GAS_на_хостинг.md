Для кого: користувач без досвіду з хостингами.

## Крок 1. Node.js і редактор

**Статус:** Node.js встановлений (згідно з твоїми кроками).

**Що ще:** редактор коду (VS Code або Cursor) — для роботи з файлами проєкту. Якщо вже використовуєш Cursor, достатньо.

## Крок 2. Вибір хостингу (детально)

Досвіду з хостингами немає — тому важливо обрати сервіс з простим інтерфейсом і, бажано, безкоштовним тарифом для старту.

### Що має вміти хостинг для бота

- Запускати Node.js-додаток 24/7.
- Давати публічний HTTPS-адресу (для webhook Telegram).
- Дозволяти задавати змінні середовища (токен бота, ключі Supabase).

### Порівняння варіантів (орієнт для початківця)

| Сервіс | Складність | Безкоштовний тариф | Плюси | Мінуси |
|--------|------------|---------------------|--------|--------|
| **Railway** | Низька | Є (обмежений) | Простий деплой з GitHub, мало кнопок, зрозумілі логи | Ліміти по годинах/місяць на free |
| **Render** | Низька | Є | Кнопка "Deploy", безкоштовні статичні та backend сервіси | Free backend засинає після неактивності (перший запит повільний) |
| **Fly.io** | Середня | Є | Потужно, дешево при рості | Більше терміналу й концепцій (регіони, машини) |
| **VPS (Timeweb, DigitalOcean тощо)** | Вища | Ні (або trial) | Повний контроль, один сервер на все | Потрібно самому налаштовувати Node, nginx, SSL |

### Рекомендація при нульовому досвіді

**Почни з Railway або Render.**

- **Railway:** підключаєш GitHub-репозиторій → налаштовуєш змінні середовища → натискаєш Deploy. Для Telegram-бота з невеликою кількістю користувачів безкоштовного ліміту часто вистачає на тестування.
- **Render:** подібно — створюєш "Web Service", підключаєш репозиторій, вказуєш команду запуску й змінні. Мінус: на free-тарифі сервіс "засинає", тому перше повідомлення в боті може прийти з затримкою 30–60 секунд; для продакшену з постійними користувачами краще платний тариф або Railway.

**Що зробити зараз:** зареєструйся на одному сервісі (наприклад, [Railway](https://railway.app) або [Render](https://render.com)), обліковий запис GitHub — теж (якщо ще немає); він знадобиться для деплою з репозиторію.

## Крок 3. Перенести логіку з GAS у Node.js

**Що робити:** створити новий проєкт (папка, `package.json`), перенести логіку з модулів GAS у код для Node.js. Замість роботи з Google Sheets — виклики API Supabase (бібліотека `@supabase/supabase-js`). State замість PropertiesService — зберігати в Supabase (таблиця станів) або в іншому сховищі за архітектурою проєкту.

**Навіщо:** GAS і Node.js — різні середовища; код треба адаптувати під Node.js і під роботу з Supabase, а не з таблицями в GAS.

---

## Крок 4. Секрети в змінних середовища

**Що:** токен Telegram-бота, URL проєкту Supabase та anon/service ключі не зберігати в коді. Локально — файл `.env` (його не комітити в Git). На хостингу — розділ "Environment" / "Variables", куди вносиш ті самі ключі.

**Навіщо:** безпека й гнучкість (один код — різні налаштування для тесту й продакшену).

---

## Крок 5. Як бот отримує оновлення від Telegram

**Що:** у Node.js-додатку приймати запити від Telegram. Два варіанти:

- **Webhook** — Telegram сам надсилає POST-запити на твою URL (наприклад `https://твій-проєкт.railway.app/webhook`). Потрібен постійний HTTPS.
- **Long polling** — твій сервер періодично питає Telegram "чи є нові повідомлення?". Може працювати навіть без публічного URL (для локальної перевірки).

Для хостингу зазвичай використовують webhook.

---

## Крок 6. Деплой на хостинг

**Що:** залити код (через Git) на обраний хостинг, вказати команду запуску (наприклад `node index.js` або `npm start`), задати змінні середовища. Переконатися, що сервіс слухає порт, який надає хостинг (часто через змінну типу `PORT`), і що зовні доступний HTTPS.

**Навіщо:** бот має працювати не лише на твоєму комп’ютері, а постійно на сервері.

---

## Крок 7. Вказати Telegram webhook на новий сервер

**Що:** через API Telegram встановити webhook на URL твого хостингу (наприклад `https://твій-проєкт.railway.app/webhook` або той, що дає обраний сервіс).

**Навіщо:** щоб усі повідомлення йшли на новий бот, а не на старий GAS.

---

## Крок 8. Перевірка і вимкнення GAS

**Що:** написати боту, пройти основні сценарії (реєстрація, меню, тренування, розклад). Якщо все коректно — у GAS вимкнути тригер або змінити/прибрати webhook, щоб старий бот більше не обробляв оновлення.

**Навіщо:** уникнути подвійної обробки й остаточно перейти на новий хостинг.

---

## Короткий порядок дій

1. Node.js + редактор — готово (Node встановлений).
2. Обрати хостинг (рекомендація: Railway або Render), зареєструватися, мати GitHub.
3. Перенести код GAS → Node.js + Supabase.
4. Секрети в `.env` локально та в налаштуваннях хостингу.
5. Реалізувати прийом оновлень (webhook або polling).
6. Задеплоїти на хостинг.
7. Встановити webhook у Telegram на новий URL.
8. Протестувати → вимкнути GAS.
