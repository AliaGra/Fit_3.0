# Бізнес-логіка MAYAG FIT — огляд для оцінки

**Повний канон:** `Бізнес-логіка_Gym_3_0_v1.1.md` (статус реалізації + детальні правила, FSM, VETO).  
**Призначення цього файлу:** стисла карта функціоналу та правил системи.

---

## 1. Продукт

Telegram-бот для **тренерів**, **учнів (student)** і **власників закладів**:
реєстрація та профіль, заміри/антропометрія, розклад тренувань (без Google Calendar),
плани тренувань з медичною фільтрацією, бібліотека вправ, абонементи залу,
групові заняття по закладах, розсилки, відгуки, нагадування (тренування / абонемент / ревізія плану / ДН).

**Runtime:** Node.js на Railway (`index.js` + `lib/`).  
**Дані:** Supabase PostgreSQL.  
**GAS:** лише експорт бібліотеки вправ з Google Sheets → імпорт у Supabase (не продакшен-бот).

---

## 2. Ролі

| Роль | Ключові можливості |
|------|-------------------|
| `coach` | Графік/слоти, клієнти, інвайти, тренування SELF/COACH, плани, типи послуг (personal/split/trio/group + offline/online/programs/nutrition), групові по клубах, звіти/тарифи, розсилка, публічна картка, Навігатор |
| `student` | Запис на слоти, виконання плану, заміри, абонемент, новини (`ads_opt_in`), відгук про тренера |
| `venue_owner` | Картка закладу, тренери, розсилка закладу, тарифи/послуги (фаза 0+) |
| Dual | Тренер може мати доступ власника (`venue_managers` + `active_menu_mode`) |

---

## 3. Основні домени (правила)

1. **Реєстрація / інвайт** — стать перед ПІБ (учень); тренер: послуги (`offline`/`online`/`programs`/`nutrition`) → типи (`personal`/`split`/`trio`/`group`); інвайт `INVITE_*` → активація з переносом даних.  
2. **Розклад** — статуси `AVAILABLE / REQUESTED / BOOKED / COMPLETED`; автопродовження слотів; нагадування 24h + 2h.  
3. **Тренування** — SELF (тренер), COACH (учні), студентський план (день → вправи → вага/повтори); `price_charged` → звіти.  
4. **Плани** — авто/вручну; медичний фільтр; активація з `valid_until`; ревізія cron; прогресія / деавтоматизація.  
5. **Профіль тіла** — заміри, `goal_*`, тип фігури (потрібен wrist), AI-аналітика (опційно).  
6. **Тип тренувань / групові (13–14.11)** — хаб у профілі (персональний підсумок); **Змінити** з Додати?/Зняти?; заняття лише з картки клубу (`venue_facets`); **Створити своє** (`local_*`); архів/відновлення через `archive_pending`/`restore_pending`.  
7. **Заклади / абонемент** — каталог, модерація; **Де треную** (`VENUES_TEACH`) vs **Де тренуюсь**; `user_venues` / `coach_venues`; абонемент з `venue_id`.  
8. **Вартість** — ціни на кнопках видів; персональний тариф клієнта зі списку; спліт/тріо — повна сума ÷2/÷3 у `price_charged`.  
9. **Розсилка** — свої клієнти; потенційні (клуби / місто / інші міста — згодом платно); ліміт 1/добу.  
10. **Відгуки** — ≥3 COMPLETED, модерація адміном, середнє на публічній картці.  
11. **ДН** — cron: за 3/2/1 день пари тренер↔учень; у день — вітання («Тренере {імʼя}!» / «{імʼя}!»).

## 4. Архітектурні VETO (коротко)

- Без магічних рядків callback — лише `lib/constants.js`.  
- Дані FSM у `bot_state`, не в `callback_data`.  
- Не відхилятись від схеми БД без міграцій.  
- Не ховати помилки порожнім `try/catch`.  
- Динамічний текст у Telegram — без небезпечного Markdown (імена/дати).

## 5. Для оцінки складності
