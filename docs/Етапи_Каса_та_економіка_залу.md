## Етап 1 — Режим збору грошей A/B у «Умовах залів» ✅

**Мета:** на кожному залі окремо для **сесій** і для **групових** зафіксувати, хто бере гроші з клієнта.

| Режим | Хто бере з клієнта | Що далі |
|--------|---------------------|---------|
| **A. Тренер-каса** (`coach`) | Тренер | Тренер віддає залу комісію |
| **B. Зал-каса** (`venue`) | Зал | Зал віддає тренеру «чисті» |

**Зроблено**
- Міграція `supabase_migration_coach_venue_economics_cash_mode.sql`
- UI: Умови залів → зал → «Хто бере оплату (сесії/групові)»
- Поля `session_cash_mode`, `group_cash_mode`

**Тест:** відкрити зал → A для сесій, B для групових → вийти й знову відкрити картку залу.

## Етап 2 — Каса: індив / спліт / тріо (день) ✅ (код)

**Вхід:** Мій профіль → **Каса** → Індив/спліт/тріо → Сьогодні / Вказати дату.

**Правила плану**
- У план ідуть лише слоти **`COMPLETED`** (проведені).
- BOOKED без відмітки / no-show → **не** в касі.
- Запис тренування через меню «Тренування» вже переводить слот у `COMPLETED` — окремий пошук `bot_training_data` не потрібен.
- Валовий = `price_charged`.
- Комісія / чисті = Умови залів (% або фікс) + режим A/B.
- Спліт/тріо: комісія залу **один раз на сесію**.
- **Кілька залів за день** → показати список залів, по кожному — своя каса.

**Звірка**
- Тренер вводить **одну** фактичну суму (ту, що здає залу або отримує від залу — залежно від A/B).
- `факт = план` → «Розбіжностей немає, суму зафіксовано» → каса дня по залу **закрита остаточно**.
- `факт ≠ план` → **заборонити** фіксацію + список: `Прізвище Ім’я — сума` (сума «здачі/отримання», не обов’язково валовий).

**Борг після фіксації**
- A: погашено борг тренера → залу (комісія).
- B: погашено борг залу → тренеру (чисті).

**Зроблено (код)**
- Міграція `supabase_migration_coach_cash_settlements.sql`
- `lib/coachCash.js` — UI; `lib/coachEconomicsCalc.buildCashSessionVenuePlans`
- Мій профіль → **Каса**; план A/B; фіксація лише при `факт = план`

**Накатити в Supabase:** `supabase_migration_coach_cash_settlements.sql`

**Тест:** 2 COMPLETED в одному залі сьогодні → план → ввід = план → зафіксовано; ввід ≠ план → список клієнтів, без фіксації.

## Етап 3 — Каса: групові (місяць) ✅ (код)

**Вхід:** Каса → Групові → зал → місяць.

**Правила**
- Групові лишаються **місячними**.
- База плану: **% від оплат абонементів** з `start_date` у цьому місяці (як у кроці 2–3).
- Режим A/B для групових — **окремий** від сесій.
- Факт: **одна сума** за місяць.
- Збіг → фіксація остаточна; розбіжність → заборонити + розшифровка (клієнт / абонемент / сума здачі).

**Зроблено (код)**
- `buildCashGroupVenuePlans` + UI в `coachCash.js` (kind `group_month`)
- Місяць = оплати абонементів з `start_date` у межах місяця; A/B **групові** окремо від сесій
- Фікс за відвідувача — поки блокує закриття (як у звітах)

**Тест:** абонемент зі start у місяці → план % → ввід факту = план → closed.

## Етап 5 — Нагадування тренеру +5 хв після старту слоту ✅ (код)

**Умова (MVP)**
- Слот `BOOKED`, є учень
- `now >= час слоту + 5 хв` (`COACH_SLOT_WATCH_MINUTES`, за замовч. 5)
- Дедуп `reminders_sent`, kind `coach_slot_open_5m`

**Зроблено**

- `GET /cron/coach-slot-watch?secret=REMINDER_CRON_SECRET` — **cron кожні 5 хв**
- Кнопки: **Відмітити** (`SCH_COMPLETE`), **Відкрити розклад**

**Пізніше (етап 5b)**
