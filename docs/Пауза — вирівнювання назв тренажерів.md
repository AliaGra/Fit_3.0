# Пауза: вирівнювання назв тренажерів у бібліотеці вправ

## Проблема

У **ExerciseLibrary_v3_medical.xlsx.json** обладнання задано **неоднорідно**:

1. **Текст** — в частині рядків поле `equipment` це вільний текст, наприклад:
   - «Блоковий тренажер, V-рукоять»
   - «Гантелі», «Штанга», «Власна вага»
   - «Inter Atletika Lever Seated Row (важільна горизонтальна тяга)»
   - «Турнік або рама з лямками», «Платформа або сходинка», «Стіна»

2. **Коди з бібліотеки** — в інших рядках уже використано `equipment_id`:
   - `EQ_BARBELL`, `EQ_DUMBBELL`, `EQ_CABLE`, `BW`, `ACC_MAT`, `ACC_FITBALL`, `ACC_BAND`, `ACC_STEP` тощо.

3. **Коди, яких немає в таблиці equipment**:
   - `EQ_INTER_SHOULDER`, `EQ_INTER_BUTTERFLY` — у міграції є лише `EQ_INTER_CHEST`, `EQ_INTER_ROW`.

Через це:
- у картці вправи можуть показуватись некоректні назви тренажерів;
- частина рядків у БД має порожній `equipment_id` або невідповідність між текстом і кодом.

## Що зробити (план)

1. **Зупинити оновлення** `equipment_id` з поточного JSON, поки не вирівняємо джерело.
2. **Вирівняти джерело** — привести бібліотеку до єдиного формату:
   - або **усюди текст** (як зараз у частині рядків), а в коді/маппінгу однозначно зводити текст → `equipment_id`;
   - або **усюди коди** — у JSON/Excel у полі обладнання лише `equipment_id` з таблиці `equipment`.
3. **Привести таблицю equipment і JSON до одного стандарту**:
   - вирішити: додати в `equipment` записи для `EQ_INTER_SHOULDER`, `EQ_INTER_BUTTERFLY` (і дати їм `name_ua`) чи замінити ці коди на існуючі (наприклад, `EQ_INTER_ROW` / інші).
   - для всіх текстових варіантів скласти **маппінг**: один варіант тексту → один `equipment_id`, і використовувати його при імпорті та оновленні.

## Корисні команди

- **Звіт по унікальних значеннях `equipment` у JSON** (текст vs код, відсутні в `equipment`):
  ```bash
  node scripts/report-equipment-from-json.js
  ```
  Результат: `data/equipment-review.json` (або вивід у консоль) — список усіх унікальних значень і пропонований/наявний `equipment_id`.

- Після заповнення маппінгу в `data/equipment-mapping.json` можна знову запускати:
  ```bash
  node scripts/update-equipment-id.js
  ```

## Файли

| Файл | Призначення |
|------|-------------|
| `data/ExerciseLibrary_v3_medical.xlsx.json` | Джерело бібліотеки (поки що змішаний формат). |
| `data/equipment-mapping.json` | Маппінг «текст або старий код» → `equipment_id` (єдине джерело правди після вирівнювання). |
| `data/equipment-review.json` | Згенерований звіт: унікальні значення з JSON + пропонований id (для ручного виправлення). |
| `supabase_migration_equipment_etap1.sql` | Таблиця `equipment` — список допустимих id і назв. |

Після вирівнювання назв і маппінгу продовжуємо етап 1 (FK, тест картки, при потребі видалення колонки `equipment`).
