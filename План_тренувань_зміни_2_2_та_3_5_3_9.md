## 2.2. getSetsRepsRest — сигнатура та врахування MC (ТЗ 14.1)

**Суть:** при `ALLOWED_WITH_MOD` зменшувати sets на 1 (мінімум 1). Сигнатура: `getSetsRepsRest(goal, level, vid?, mcStatus?)`.

### Файл: `lib/planGenerator.js`

**1) Замінити функцію:**

```javascript
/** sets, reps, rest_sec за ціллю та рівнем (таблиці 4.3, 4.4). При mcStatus === 'ALLOWED_WITH_MOD' — sets зменшуємо на 1 (мін. 1). */
function getSetsRepsRest(goal, level, vid, mcStatus) {
  const g = goal || GOALS.KEEP;
  let sets = 3;
  let reps = '10–15';
  let restSec = 75;

  if (g === GOALS.LOSE) {
    sets = 3;
    reps = '15–20';
    restSec = level === LEVELS.BEGINNER ? 90 : 60;
  } else if (g === GOALS.GAIN) {
    sets = level === LEVELS.BEGINNER ? 3 : 4;
    reps = level === LEVELS.BEGINNER ? '12–15' : '6–10';
    restSec = level === LEVELS.ADVANCED ? 60 : 90;
  }

  if ((mcStatus || '').toUpperCase() === 'ALLOWED_WITH_MOD') {
    sets = Math.max(1, sets - 1);
  }
  return { sets, reps, restSec };
}
```

**2) У `generateTrainingPlan`** при формуванні вправ для кожного дня передавати в `getSetsRepsRest` також `mcStatus` по вправі. Зараз виклик один на весь план:

```javascript
const { sets, reps, restSec } = getSetsRepsRest(goal, level);
```

Для повної відповідності ТЗ можна для кожної вправи в циклі брати `getSetsRepsRest(goal, level, ex.vid, ex.medicalStatus)` і зберігати в об’єкт вправи свої sets/reps (або лишити один виклик для всього плану і передавати тільки `goal`, `level` — тоді mcStatus у getSetsRepsRest не використовувати, але сигнатуру залишити для майбутнього).

**Мінімальний варіант:** лише розширити сигнатуру і логіку ALLOWED_WITH_MOD у `getSetsRepsRest(goal, level, _vid, mcStatus)`; у `generateTrainingPlan` залишити один виклик `getSetsRepsRest(goal, level)` (mcStatus не передавати), щоб нічого не ламати. Пізніше можна передавати mcStatus по вправі.

**3) У `lib/trainingPlan.js`** (рядок ~438): виклик залишити з двома аргументами, якщо там не потрібна індивідуальна логіка по вправі:

```javascript
const sr = planGenerator.getSetsRepsRest(plan.goal || 'keep', plan.level || 'beginner');
```

Якщо захочете враховувати MC при ручному додаванні вправи — передати третій/четвертий аргумент з контексту вправи.

## 3.5. Поле revision_weeks у UI (ручне створення плану)

**Суть:** після вибору рівня (PLAN_LEVEL) додати крок «Термін ревізії плану» з кнопками «За замовчуванням» та «Вказати (тижнів)»; при «Вказати» — введення числа або кнопки 4/6/8/10; зберігати в state і передавати в `insertTrainingPlan`.

### Файл: `lib/constants.js`

Додати callback для кроку ревізії (опційно окремий префікс, наприклад):

```javascript
PLAN_REVISION_WEEKS: 'PLAN_REVISION_WEEKS',  // якщо ще немає
```

І FSM-стан (якщо ще немає):

```javascript
PLAN_SET_REVISION: 'plan_set_revision',
```

### Файл: `lib/trainingPlan.js`

**1) Після вибору рівня замість одразу показувати «Скільки днів» — показати крок ревізії.**

Після обробки `PLAN_LEVEL` (рядок ~291) замість виклику `askPlanDays(chatId)` викликати нову функцію `askPlanRevisionWeeks(chatId)`.

**2) Додати функції:**

    [{ text: 'Вказати тижнів', callback_data: CONSTANTS.CALLBACK_PREFIXES.PLAN_REVISION_INPUT + ':' + (state?.planStudentChatId || '') }]

  await Helpers.sendKeyboard(chatId, 'Термін ревізії плану (після скількох тижнів пропонувати оновити план)? За замовчуванням для твого рівня: ' + defWeeks + ' тиж.', keyboard);

**3) Обробка callback:**

- `PLAN_REVISION_DEFAULT` — зберегти в state `planManualRevisionWeeks: null` (означає «за замовчуванням»), викликати `askPlanDays(chatId)`.
- `PLAN_REVISION_INPUT` — показати кнопки 4/6/8/10 (або перехід у ввід текстом), викликати `askPlanRevisionWeeksNumber(chatId)`.
- `PLAN_REVISION_WEEKS` з параметром N — зберегти `planManualRevisionWeeks: N`, викликати `askPlanDays(chatId)`.

**4) У блоці PLAN_DAYS** при виклику `insertTrainingPlan` додати:

```javascript
revisionWeeks: state.planManualRevisionWeeks != null ? parseInt(state.planManualRevisionWeeks, 10) : undefined
```

(у об’єкт, який передається в `supabase.insertTrainingPlan`; у supabase вже є підтримка `plan.revisionWeeks`).

**5) У `askPlanLevel`** після збереження рівня викликати `askPlanRevisionWeeks(chatId)` замість `askPlanDays(chatId)`.

Потрібно додати константи в `constants.js`: `PLAN_REVISION_DEFAULT`, `PLAN_REVISION_INPUT`, `PLAN_REVISION_WEEKS` та FSM `PLAN_SET_REVISION`, і в `router.js` додати ці префікси до списку plan-обробників.

## 3.6. Кількість вправ за таблицею 4.4 (діапазони за рівнем)

**Суть:** замість фіксованого `exerciseCount` задавати діапазон (min–max) і вибирати випадкове число у межах або брати max (за бажанням).

### Файл: `lib/planGenerator.js`

**1) Додати таблицю діапазонів (за Логікою 4.4):**

```javascript
/** Діапазон кількості вправ на день за типом дня та рівнем (таблиця 4.4). */
const EXERCISE_COUNT_RANGE = Object.freeze({
  full_body: { beginner: [5, 6], intermediate: [6, 7], advanced: [7, 8] },
  upper_lower: { beginner: [4, 5], intermediate: [5, 6], advanced: [6, 7] },
  ppl: { intermediate: [5, 6], advanced: [6, 8] }
});

function getExerciseCountForDay(dayType, level) {
  const typeKey = dayType === 'full_body' ? 'full_body' : (dayType === 'push' || dayType === 'pull' || dayType === 'legs' ? 'ppl' : 'upper_lower');
  const range = EXERCISE_COUNT_RANGE[typeKey] && EXERCISE_COUNT_RANGE[typeKey][level];
  if (range) {
    const [min, max] = range;
    return min + Math.floor(Math.random() * (max - min + 1));
  }
  return dayType === 'full_body' ? 6 : 6;
}
```

**2) У `getSplitSchemeAndDays`** замість фіксованих `exerciseCount: 5`, `exerciseCount: 6` обчислювати:

```javascript
exerciseCount: getExerciseCountForDay('full_body', level)   // для full_body
exerciseCount: getExerciseCountForDay('upper_lower', level) // для upper/lower
exerciseCount: getExerciseCountForDay('ppl', level)         // для push/pull/legs
```

Для кожного дня викликати `getExerciseCountForDay(dayType, level)` при формуванні `dayConfigs`. Якщо один день «upper», інший «lower» — передавати відповідно `'upper_lower'` для обох (або розділити upper_lower на upper і lower з тим самим діапазоном).

## 3.7. MC018 — окрема логіка підбору (ожиріння, class1/2/3)

**Суть:** при наявності MC018 у `user_medical_conditions` визначити клас (за severity: class1/class2/class3 або за BMI); у підборі вправ виключати/пріоритизувати вправи згідно з правилами (стоячи з штангою, стрибки, тощо).

**Передумова:** у `exercise_library` потрібні ознаки типу вправи (позиція, інвентар). Якщо є колонки на кшталт `position` (standing/sitting/lying), `equipment` (barbell/cable/machine) — використовувати їх. Якщо немає — тимчасово використовувати евристики по назві/обладнанню.

### Файл: `lib/supabase.js` — getExercisesForPlanByGroupLevel2

Додати в `select` поле `equipment`, якщо воно є в таблиці:

```javascript
.select('id, group_level1, group_level2, group_level3, name_ua, name_ru, difficulty, vid, equipment, medical_contraindications, medical_limitations, safe_for, modifications')
```

І в мапінг результату:

```javascript
equipment: (r.equipment || '').toString().toLowerCase(),
```

### Файл: `lib/planGenerator.js`

**1) Визначити клас MC018** за severity з профілю (або за BMI з user):

```javascript
function getMc018Class(userMedConditions, user) {
  const mc = (userMedConditions || []).find((m) => (m.mc_code || '').toUpperCase() === 'MC018');
  if (!mc) return null;
  const s = (mc.severity || '').toLowerCase();
  if (s.indexOf('class1') >= 0 || s === 'class1') return 1;
  if (s.indexOf('class2') >= 0 || s === 'class2') return 2;
  if (s.indexOf('class3') >= 0 || s === 'class3') return 3;
  return 1;
}
```

**2) У `pickExercisesForDay`** додати параметр у `options`, наприклад `mc018Class`:

- Якщо `mc018Class === 2` або `3`: виключати вправи, де в назві або equipment є «штанга» і вважається «стоячи» (наприклад name містить «стоя», «присідання з штангою» — евристика, або окреме поле position).
- Якщо `mc018Class === 3`: лишати тільки сидячи/лежачи (за назвою: «лежачи», «сидячи», «в тренажері» тощо), виключати «стриб», «прыжок».
- Якщо `mc018Class === 1`: не виключати повністю, але можна понизити пріоритет важких присідань з штангою (наприклад _sortOrder вище).

**3) У `generateTrainingPlan`** перед циклом по днях:

```javascript
const mc018Class = getMc018Class(userMedConditions, user);
```

І в `pickExercisesForDay` передавати в options: `mc018Class`.

**Приклад фільтра в `pickExercisesForDay`** (після існуючих перевірок):

```javascript
if (options.mc018Class != null) {
  const c = options.mc018Class;
  const name = ((ex.name || '') + ' ' + (ex.name_ua || '') + ' ' + (ex.name_ru || '')).toLowerCase();
  const equip = (ex.equipment || '').toLowerCase();
  if (c >= 2 && (equip.indexOf('штанга') >= 0 || name.indexOf('штанга') >= 0) && (name.indexOf('стоя') >= 0 || name.indexOf('присідання') >= 0)) continue;
  if (c >= 3) {
    if (name.indexOf('стриб') >= 0 || name.indexOf('прыжок') >= 0 || name.indexOf('стрибок') >= 0) continue;
    if (name.indexOf('лежачи') < 0 && name.indexOf('сидячи') < 0 && name.indexOf('в тренажері') < 0 && name.indexOf('тренажер') < 0) continue; // лише сидячи/лежачи/тренажер
  }
}
```

Це спрощені евристики; краще мати в БД поля `position` та `equipment_type`.

## 3.8. Female — важка вага для грудей при goal ≠ gain

**Суть:** при `gender === 'female'` і `goal !== 'gain'` виключати або понижувати пріоритет вправ на груди з «важкою вагою» (наприклад штанга, базова/важка).

### Файл: `lib/planGenerator.js` — у `pickExercisesForDay`

Після формування `allowed` (або всередині циклу по `exercises`) додати умову:

- Якщо `gender === 'female'` і `goal !== 'gain'` і `ex.groupLevel2 === 'Груди'`:
  - Визначити «важка вага» через `vid` (наприклад «базова») або `equipment`/назву (штанга, жим лежачи).
  - Або пропускати такі вправи (`continue`), або ставити їм `_sortOrder = 10`, щоб вони йшли в кінець і рідше потрапляли в вибір.

**Приклад (після рядка з `allowed.push`):**

```javascript
if ((gender || '').toLowerCase() === 'female' && goal !== GOALS.GAIN && (ex.groupLevel2 || '') === 'Груди') {
  const vid = (ex.vid || '').toLowerCase();
  const equip = (ex.equipment || '').toString().toLowerCase();
  const name = (ex.name || '').toLowerCase();
  const isHeavyChest = vid.indexOf('базов') >= 0 || equip.indexOf('штанга') >= 0 || name.indexOf('жим лежачи') >= 0 || name.indexOf('штанга') >= 0;
  if (isHeavyChest) continue; // або не push, або push з _sortOrder 10
}
```

Якщо вирішити не виключати, а лише понижувати пріоритет — не робити `continue`, а в об’єкті, що пушиться в `allowed`, встановити `_sortOrder: 10` для таких вправ.

## 3.9. Fallback при малому пулі після Anti-Repeat (ТЗ 6.7)

**Суть:** якщо після застосування правил А і Б `allowed.length < dayConfig.exerciseCount`, повторити підбір без виключення за правилом Б (порожній `previousPlanIsolationIds`) і залоговати факт.

### Файл: `lib/planGenerator.js` — функція `pickExercisesForDay`

**1)** Після формування масиву `allowed` (після сортування) перевірити:

```javascript
let usePrevIsolationIds = prevIsolationIds;
if (allowed.length < dayConfig.exerciseCount && prevIsolationIds.size > 0) {
  if (process.env.DEBUG === '1') {
    console.log('[planGenerator] Fallback: rule B relaxed (pool ' + allowed.length + ' < ' + dayConfig.exerciseCount + ')');
  }
  usePrevIsolationIds = new Set();
}
```

**2)** Далі використовувати `usePrevIsolationIds` замість `prevIsolationIds` у фільтрі «ізоляція з попереднього плану». Зараз перевірка:

```javascript
if (isIsolation && prevIsolationIds.has(ex.id)) continue;
```

Потрібно спочатку збирати `allowed` без цієї перевірки, потім перевірити `allowed.length >= dayConfig.exerciseCount`. Якщо ні — перебрати exercises знову і формувати `allowed` без виключення за `prevIsolationIds` (тобто з `usePrevIsolationIds = new Set()`), і використати цей другий `allowed` для weightedSample.

Простіша реалізація: один цикл, але змінна `effectivePrevIds = prevIsolationIds`. Після першого циклу по exercises: якщо `allowed.length < count`, очистити `allowed`, встановити `effectivePrevIds = new Set()` і пройти цикл по exercises ще раз (без зміни інших фільтрів), заповнити `allowed` знову. Потім використати `allowed` для weightedSample. Логування: при другому проході викликати `console.log('[planGenerator] Fallback: rule B relaxed for day', dayConfig.dayNumber)`.

**Приклад структури:**

```javascript
let effectivePrevIds = prevIsolationIds;
let allowed = [];

function buildAllowed() {
  allowed = [];
  for (const ex of exercises) {
    // ... всі існуючі перевірки, але замість prevIsolationIds.has(ex.id) використовувати effectivePrevIds.has(ex.id) ...
    if (isIsolation && effectivePrevIds.has(ex.id)) continue;
    // ...
    allowed.push(...);
  }
  allowed.sort((a, b) => a._sortOrder - b._sortOrder);
}

buildAllowed();
const count = Math.min(dayConfig.exerciseCount, allowed.length);
if (count < dayConfig.exerciseCount && effectivePrevIds.size > 0) {
  effectivePrevIds = new Set();
  buildAllowed();
  if (process.env.DEBUG === '1') console.log('[planGenerator] Fallback: rule B relaxed for day', dayConfig.dayNumber);
}
const finalCount = Math.min(dayConfig.exerciseCount, allowed.length);
// далі weightedSample(allowed, finalCount, ...)
```

Щоб не дублювати код циклу, варто винести логіку фільтрації в одну функцію, яка приймає `effectivePrevIds` і заповнює `allowed`.
