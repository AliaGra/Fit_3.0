# Вартість тренувань та статистика (Варіант А)

## Відповіді на питання

### 1. Де записувати вартість?

**Рекомендація: окремий лист "Pricing" (Прайс), не розширювати USERS.**

- **Чому не USERS:** таблиця Users вже має 20 колонок (A–T); додавання 4+ колонок (ціна персональна/спліт/тріо, валюта) ускладнює структуру і змішує профіль з тарифами. Для учнів ці колонки були б порожніми.
- **Лист Pricing:** один рядок на комбінацію (тренер + опційно учень). Якщо StudentId порожній — тарифи тренера за замовчуванням; якщо вказаний — індивідуальна вартість для цього учня.

**Структура листа Pricing (мінімальний варіант):**

| Колонка | Опис |
|--------|------|
| A CoachId | ChatID тренера |
| B StudentId | ChatID учня (порожньо = тариф за замовчуванням для всіх) |
| C PricePersonal | Вартість персональної (число, ціле) |
| D PriceSplit | Вартість спліт (число) |
| E PriceTrio | Вартість тріо (число) |
| F Currency | Валюта (наприклад UAH, USD) |
| G UpdatedAt | Дата оновлення |

Один рядок на тренера з порожнім StudentId = тариф за замовчуванням. Додаткові рядки з заповненим StudentId = індивідуальна вартість для учня.

---

### 2. Як записувати вартість для спліт/тріо?

**Ділити вартість тренування на кількість учнів; у звіті по учню показувати "його" частину.**

- Тренер вводить **ціну за заняття** (наприклад спліт = 1000 грн за двійку, тріо = 1200 грн за трійку).
- У **WorkoutSchedule** у кожного слота (один слот = один учень) при переході в COMPLETED зберігається **сума з одного учня**:
  - персональна: `PriceCharged = ціна персональної`;
  - спліт: `PriceCharged = ціна спліту / 2`;
  - тріо: `PriceCharged = ціна тріо / 3`.
- У звіті "дохід за період": сума по всіх слотах з COMPLETED = загальний дохід; по учню — сума по слотах цього учня (вже приведена до "з одного учня").

Тобто в таблиці зберігається **вже поділена** сума на учня, щоб не дублювати логіку при кожному звіті.

---

### 3. Як фіксувати зміну вартості? Чи потрібен лист "Прайс" (історія)?

**Поточна вартість:** лист **Pricing** (опис вище) — завжди актуальні тарифи.

**Історія змін (опційно):** окремий лист **PriceHistory** для аудиту та аналізу "яка ціна була на дату X":

| Колонка | Опис |
|--------|------|
| A CoachId | ChatID тренера |
| B StudentId | порожньо або ChatID учня |
| C TrainingType | PERSONAL / SPLIT / TRIO |
| D Price | Введена вартість |
| E Currency | Валюта |
| F ValidFrom | Дата/час внесення |

- При кожній зміні ціни (ввод/зміна/індивідуальна) додається один рядок у PriceHistory. Звіти за минулі періоди можна будувати по PriceHistory (ціна на дату тренування) або спростити: **на момент позначення тренування як "виконане" (COMPLETED)** зберігаємо поточну ціну з Pricing у слот (PriceCharged, Currency). Тоді статистика завжди "як було на момент проведення" без пошуку в історії.

**Висновок:** достатньо листа **Pricing** для поточної вартості та запису **PriceCharged + Currency** у WorkoutSchedule при COMPLETED. Лист **PriceHistory** — за бажанням для історії змін тарифів.

---

## Розширення WorkoutSchedule

Додати дві колонки (після існуючих A–H):

| I PriceCharged | Число. Сума з одного учня (вже поділена для спліт/тріо). Заповнюється при STATUS = COMPLETED. |
| J Currency     | Рядок. Валюта (наприклад UAH). |

Заповнення: у момент переходу слота в COMPLETED (кнопка "Завершити тренування" або "Підтвердити присутність") зчитується поточна ціна з Pricing (для даного тренера + учня + типу тренування), ділиться на 1/2/3 за типом, результат пишеться в PriceCharged та Currency по кожному слоту.

---

## Функціонал (варіант А) — коротко

1. **У картці учня (меню тренера):** показувати вид тренування та застосовні ціни: персональна / спліт / тріо (з Pricing: індивідуальні або тариф тренера за замовчуванням).
2. **Розділ "Мої учні":**
   - Кнопка **"Ввести вартість тренування"** → підменю: персональна (ціна + валюта), спліт (ціна + валюта), тріо (ціна + валюта). Введення цілими числами (формат 000.0 — після коми завжди 0).
   - Кнопка **"Індивідуальна вартість"** → вибір учня → далі те саме меню введення цін по типах.
   - Кнопка **"Змінити вартість"** → стандартне меню введення (тип + ціна) для оновлення поточних тарифів.
3. **Відлік вартості:** з моменту внесення ціни вона вважається "поточною"; при наступному позначенні тренування як виконаного (COMPLETED) у слот записується саме ця поточна ціна (з поділом на 1/2/3 за типом).
4. **Звіти:** у розділі "Звіти" тренера додати підпункт "Статистика за вартістю" (або розширити існуючий звіт): за період — кількість тренувань + сума (по PriceCharged з WorkoutSchedule, Status = COMPLETED), по типах та по учнях за бажанням.

## Підсумок рішень

| Питання | Рішення |
|---------|---------|
| Де записувати? | Лист **Pricing** (CoachId, StudentId?, PricePersonal, PriceSplit, PriceTrio, Currency, UpdatedAt). |
| Спліт/тріо? | Ділити ціну заняття на 2 або 3; у WorkoutSchedule зберігати вже суму з одного учня (PriceCharged). |
| Зміна вартості? | Поточна вартість — лист Pricing. Опційно лист **PriceHistory** для історії змін. При COMPLETED у слот пишемо поточну ціну (PriceCharged, Currency). |
