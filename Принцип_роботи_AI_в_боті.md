# Принцип роботи AI в боті FIT 3.0

**Коротко:** AI (OpenAI GPT-4o-mini) у боті використовується **опційно** тільки для «м’якого» контенту: коментарі до вправ, текст нагадувань, короткий аналіз невиконання. Підбір вправ, sets/reps, медична фільтрація, розклад — залишаються **детермінованими** (без AI). Якщо AI вимкнено або API не відповідає — бот працює як раніше, без збоїв.

---

## 1. Умова увімкнення AI

- У середовищі (Railway) задано:
  - **OPENAI_API_KEY** — ключ API OpenAI (sk-...).
  - **AI_ENABLED** = **true** (латинськими).
- Модуль **lib/ai/aiClient.js** перевіряє: `AI_ENABLED === 'true'` і наявність ключа. Якщо умова не виконана — усі виклики AI повертають **null**, бот використовує звичайний (fallback) сценарій.
- Додатково: **AI_MODEL** (за замовчуванням gpt-4o-mini), **AI_MAX_TOKENS**, **AI_TIMEOUT_MS** — для обмеження витрат і часу очікування.

**Принцип:** AI ніколи не є обов’язковим. Кожна функція перевіряє `aiClient.isEnabled()` і при вимкненому AI або помилці API просто не викликає OpenAI і не ламає сценарій.

---

## 2. Три сценарії використання AI

### 2.1. Коментарі тренера в планах

**Коли спрацьовує:** тренер генерує план учню через **«Новий план» → «Авто-підбір» → «Генерувати»**. Після того як алгоритм уже підібрав вправи по днях (медичні фільтри, ціль, рівень тощо), для **кожного дня** окремо викликається AI.

**Що відправляється в OpenAI:**
- Системний промпт: роль «досвідчений фітнес-тренер», правила (коротко, українською, до 100 символів на вправу, враховувати медичні обмеження).
- Користувацький промпт: профіль учня (ім’я, вік, ціль, рівень, медичні стани), тип дня (full_body, upper, lower тощо), список вправ цього дня (id, назва, medicalStatus, sets, reps).

**Що очікується відповіддю:** один JSON-об’єкт, наприклад:
`{ "123": "коментар до вправи 123", "124": "коментар до вправи 124", "day_summary": "короткий підсумок дня" }`.

**Що робить бот далі:**
- Парсить JSON, валідує через **aiValidator** (тип, довжина, без небезпечних символів).
- Для кожної вправи в плані в поле **notes** підставляє коментар з відповіді (за id вправи).
- Зберігає план у БД уже з коментарями; при перегляді плану в боті під вправою показується рядок типу «💬 Тренер: …».
- Успішний виклик логують у таблицю **ai_generated_content** (content_type = plan_comment, entity_id, tokens, cost).

**Fallback:** якщо AI вимкнено, помилка API або невалідна відповідь — коментарі не додаються, план зберігається з порожніми або дефолтними notes. Генерація плану не падає.

---

### 2.2. Розумні нагадування

**Коли спрацьовує:** cron викликає **GET /cron/reminders**. Бот обчислює «вікно» (наприклад, тренування через 2 години, змінна REMINDER_HOURS_BEFORE), отримує з БД слоти з записаними учнями в цьому вікні. Для **кожного** такого слота перевіряє, чи вже надсилалося нагадування (таблиця reminders_sent), і якщо ні — формує текст нагадування.

**Що відправляється в OpenAI:**
- Системний промпт: роль «фітнес-тренер, який надсилає персональні нагадування», правила (мотиваційний тон, до ~150 символів, українська, без посилань).
- Користувацький промпт: дата/час слота, ім’я учня, ім’я тренера, останні тренування учня (наприклад, за 30 днів — дата, кількість вправ/підходів) з **getStudentRecentWorkoutsSummary**.

**Що очікується:** вільний текст (не JSON) — один короткий абзац нагадування.

**Що робить бот далі:**
- Валідує текст (довжина, відсутність посилань) через **aiValidator.validateReminder**.
- Якщо валідно — відправляє учню повідомлення з префіксом «⏰ Нагадування» і цим текстом.
- Якщо AI вимкнено або повернув null/невалідний текст — відправляє **фіксований** текст на кшталт: «У тебе сьогодні тренування! 📅 дата о час 👨‍🏫 Тренер».
- Позначає слот у reminders_sent, при успішному AI-виклику логує в **ai_generated_content** (content_type = reminder, entity_id = slot.id).

**Принцип:** нагадування завжди відправляється; AI лише підставляє персоналізований текст замість шаблону.

### 2.3. Аналіз невиконання вправ

**Коли спрацьовує:** учень **завершує тренування за планом** (кнопка «Завершити тренування»). Після збереження даних тренування бот перевіряє по кожній вправі дня: чи виконано мінімум підходів. Поріг — **80%** (константа FAILURE_THRESHOLD): якщо `completedSets < plannedSets * 0.8`, вправа потрапляє в список «невиконаних».

**Що відправляється в OpenAI:**
- Системний промпт: роль «досвідчений тренер», формат відповіді JSON — поля student_message, coach_message, notify_coach, suggested_changes; підтримуючий тон, українська.
- Користувацький промпт: список невиконаних вправ (назва, completedSets/plannedSets, вага, причина якщо є), історія тренувань за останні 14 днів (дати, кількість записів), тривалість тренування, самопочуття (якщо є).

**Що очікується:** JSON, наприклад:
`{ "student_message": "текст учню", "coach_message": "текст тренеру", "notify_coach": true/false, "suggested_changes": ["..."] }`.

**Що робить бот далі:**
- Парсить JSON, валідує через **aiValidator.validateFailureAnalysis**.
- Учню відправляє повідомлення «💡 Аналіз тренування: » + student_message.
- Якщо **notify_coach === true** — тренеру (coachId учня) відправляє coach_message.
- Логує виклик у **ai_generated_content** (content_type = failure_analysis, entity_id = chatId або session).

**Fallback:** якщо AI вимкнено або помилка — нічого не відправляється (ні учню, ні тренеру). Завершення тренування та збереження даних відбуваються як завжди.

## 3. Загальні принципи

| Аспект | Реалізація |
|--------|------------|
| **Безпека** | У промпти не передається вся бібліотека вправ (~31К токенів), тільки відібрані вправи/дані для конкретного запиту. Відповіді валідуються (довжина, типи, без посилань/тегів). |
| **Вартість** | Модель gpt-4o-mini; кожен виклик логується в ai_generated_content (tokens_used, cost_usd). Можна аналізувати витрати по content_type та даті. |
| **Таймаут** | Виклик OpenAI обмежений по часу (AI_TIMEOUT_MS); при перевищенні повертається null, спрацьовує fallback. |
| **Мова** | Системні промпти та очікування — українська мова для всього контенту, що бачить користувач. |

Підсумок: **AI доповнює бота трьома конкретними функціями (коментарі, нагадування, аналіз невиконання), не замінює логіку планів чи розкладу і при вимкненні або збої не ламає роботу бота.**
