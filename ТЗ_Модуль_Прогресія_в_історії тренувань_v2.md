## 1. Мета

При перегляді конкретного тренування в історії — показувати порівняння показників кожної вправи (вага/повтори) з попереднім виконанням цієї ж вправи цим же користувачем. Учень бачить свій прогрес одразу, без додаткових дій.

## 2. Контекст виклику

Функція `showHistoryDetail` в `lib/history.js` викликається коли учень обирає конкретне тренування зі списку історії.

Дані поточного тренування беруться з `bot_training_data` по `training_session_id`.

## 3. Нова функція в `lib/supabase.js`

### `getLastExercisePerformance(chatId, exerciseId, beforeDate)`

Повертає найкращий підхід цієї вправи для цього користувача **до** вказаної дати.

```javascript
async function getLastExercisePerformance(chatId, exerciseId, beforeDate) {
  const { data, error } = await supabase
    .from('bot_training_data')
    .select('weight, reps, date')
    .eq('chat_id', String(chatId))
    .eq('exercise_id', exerciseId)
    .lt('date', beforeDate)
    .order('date', { ascending: false })
    .limit(20); // Беремо останні 20 записів щоб знайти найкращий підхід

  if (error || !data || data.length === 0) return null;

  // Найкращий підхід — максимальний добуток weight × reps
  return data.reduce((best, row) => {
    const volume = (row.weight || 0) * (row.reps || 0);
    const bestVolume = (best.weight || 0) * (best.reps || 0);
    return volume > bestVolume ? row : best;
  });
}
```

**Повертає:** `{ weight, reps, date }` або `null` (якщо записів немає або помилка БД).

## 4. Логіка визначення найкращого підходу поточного тренування

Для порівняння береться найкращий підхід **поточного** тренування — також за добутком `weight × reps`.

```javascript
function getBestSet(sets) {
  // sets — масив підходів вправи поточного тренування
  // кожен елемент: { weight, reps }
  if (!sets || sets.length === 0) return null;

  return sets.reduce((best, set) => {
    const volume = (set.weight || 0) * (set.reps || 0);
    const bestVolume = (best.weight || 0) * (best.reps || 0);
    return volume > bestVolume ? set : best;
  });
}
```

## 5. Логіка визначення дельти і маркера

```javascript
function calcDelta(current, previous) {
  // current, previous: { weight, reps } або null

  // Попередніх даних немає (перше тренування) — дельта не відображається
  if (!previous) return { marker: null, weightDelta: null, repsDelta: null };

  // Помилка БД — попередні дані null через помилку, не через відсутність
  // (розрізняємо в getLastExercisePerformance: повертає null в обох випадках)
  // → показуємо нейтральний маркер ➡️
  // Примітка: розрізнення "немає даних" vs "помилка БД" — за потреби
  // можна додати окремий sentinel, поки що обидва = null → без маркера

  const wCurr = current.weight || 0;
  const wPrev = previous.weight || 0;
  const rCurr = current.reps || 0;
  const rPrev = previous.reps || 0;

  const weightDelta = wCurr - wPrev;
  const repsDelta = rCurr - rPrev;

  let marker;

  // Вправи з вагою 0 (віджимання, планка) — порівнювати тільки повтори/час
  if (wCurr === 0 && wPrev === 0) {
    if (repsDelta > 0)  marker = '📈';
    else if (repsDelta < 0) marker = '📉';
    else marker = '➡️';
    return { marker, weightDelta: null, repsDelta };
  }

  // Прогрес: вага зросла І повтори не впали
  if (weightDelta > 0 && repsDelta >= 0) marker = '📈';
  // Прогрес по повторах: вага та сама, повтори зросли
  else if (weightDelta === 0 && repsDelta > 0) marker = '📈';
  // Спад: вага впала АБО (вага та сама і повтори впали)
  else if (weightDelta < 0 || (weightDelta === 0 && repsDelta < 0)) marker = '📉';
  // Вага зросла але повтори впали — нейтрально (не однозначний прогрес)
  else if (weightDelta > 0 && repsDelta < 0) marker = '➡️';
  // Все однакове
  else marker = '➡️';

  return { marker, weightDelta, repsDelta };
}
```

## 6. Оновлення `formatDetailText` в `lib/history.js`

### Алгоритм для кожної вправи:

```
1. Зібрати всі підходи вправи з поточного тренування (groups[exerciseName])
2. Визначити найкращий підхід поточного тренування через getBestSet()
3. Викликати getLastExercisePerformance(chatId, exerciseId, currentDate)
4. Визначити дельту через calcDelta(bestSet, lastPerformance)
5. Сформувати текст вправи з маркером і дельтою
```

### Формат виводу кожної вправи:

```
1️⃣ Жим штанги лежачи 📈
Підхід 1: 82.5кг × 8 повт. (+2.5кг)
Підхід 2: 82.5кг × 7 повт.
⏮ Попередній макс: 80кг × 8 повт.
```

```
2️⃣ Планка ➡️
Підхід 1: 0кг × 60 повт.
⏮ Попередній макс: 0кг × 60 повт.
```

```
3️⃣ Присід зі штангою  ← (без маркера — перше тренування)
Підхід 1: 60кг × 10 повт.
```

```
4️⃣ Тяга гантелі ➡️  ← (нейтральний маркер — помилка БД або неоднозначна дельта)
Підхід 1: 25кг × 10 повт.
```

### Правила формування рядка дельти:

| Ситуація | Рядок після підходу |
|---|---|
| Вага зросла | `(+X кг)` поряд з підходом де вага краща |
| Вага впала | `(-X кг)` поряд з підходом де вага краща |
| Вага та сама, повтори зросли | `(+X повт.)` |
| Вага та сама, повтори впали | `(-X повт.)` |
| Вага зросла, повтори впали | нічого (маркер ➡️ достатньо) |
| Вправа з вагою 0 | тільки `(+X повт.)` або `(-X повт.)` |

Дельта відображається **тільки поряд з найкращим підходом** (за `weight × reps`). Інші підходи — без дельти.

### Рядок "Попередній макс":

Відображається **завжди** якщо `lastPerformance != null`:
```
⏮ Попередній макс: {weight}кг × {reps} повт.
```

Якщо `lastPerformance === null` і це перше тренування (не помилка БД) — рядок не відображається.

## 7. Обробка граничних випадків

| Випадок | Поведінка |
|---|---|
| Перше тренування (немає попередніх записів) | Маркер не відображається, рядок "Попередній макс" відсутній |
| Помилка БД (`getLastExercisePerformance` → `null`) | Маркер `➡️`, рядок "Попередній макс" відсутній |
| Вправа з вагою 0 (віджимання, планка) | Порівнювати тільки повтори/час, вагову дельту не показувати |
| Підхід з `weight = null` або `reps = null` | Вважати як 0 при розрахунку об'єму |
| Автопрогресія спрацювала (система додала вагу) | Учень бачить `📈 (+2.5кг)` — підтвердження успіху |

---

## 8. Вплив прогресивного плану

Дані тренувань завжди пишуться в `bot_training_data` незалежно від типу плану (`generation_mode = 'simple'` або `'progressive'`). Логіка `getLastExercisePerformance` читає з `bot_training_data` — тому працює однаково для обох типів планів без змін.
