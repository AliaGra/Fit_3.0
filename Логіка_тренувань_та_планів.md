# Логіка тренувань та створення планів

**Версія:** 1.1  
**Дата:** 21.02.2026  
**Призначення:** Єдиний опис бізнес-логіки тренувань (без плану та за планом), створення планів (вручну та авто-підбір), виконання плану учнем, прогресія та ревізія. Документ доповнюється при змінах у продукті.

**Джерела:** Логіка складання плану тренувань v1.1, Технічне завдання «План тренувань», Бізнес-логіка Gym 3.0, Зміни_логіки_та_функціоналу.md, поточний код (lib/training.js, lib/trainingPlan.js, lib/planGenerator.js).

## 1. Загальний огляд потоків

| Потік | Учасник | Вхід | Результат |
|-------|---------|------|-----------|
| **Вільне тренування** | Тренер (моє тренування) або тренер + учень | Вибір типу → групи → вправи → кількість підходів/кругів → ввід ваги/повторів | Записи в `bot_training_data`, без плану |
| **Тренування за планом** | Учень (або тренер за учня) | Активний план → вибір дня → вправи дня | Записи в `bot_training_data`, автопрогресія/деавтоматизація по плану |
| **План вручну** | Тренер | Назва → ціль → термін ревізії → дні/тиж → додавання вправ по днях | Запис у `training_plans` + `training_plan_exercises` |
| **Авто-план** | Тренер | Вибір учня → підтвердження параметрів (або кількість вправ) → Генерувати | Генерація плану за профілем учня, запис у БД |

## 2. Тренування без плана (вільне тренування)

### 2.1 Вхід у потік

- **Тренер:** Тренування → «Моє тренування» (mode SELF) або Тренування → «Тренування учнів» → вибір учня → «Вільне тренування» (без активного плану).
- Слоти розкладу для «Моє тренування» не створюються; для тренування учня — створюються при першому записі (findOrCreateSlotForCoachSession).

### 2.2 Вибір типу виконання

Перед вибором груп м'язів користувач обирає:

- **Одиночне (1 вправа)** — одна вправа за раз, потім вибір наступної групи або завершення.
- **Сет (мін. 2 вправи)** — формується список вправ (мін. 2), потім вибір кількості кругів і виконання по колу.

Константи: `TRAINING_EXEC_TYPE_SINGLE`, `TRAINING_EXEC_TYPE_SET`. Стан: `TRAINING_EXERCISE_TYPE`, `trainingExecutionType`.

### 2.3 Вибір вправ

- Групи м'язів: ієрархія з `constants.GROUPS_BY_TOP` (Верх, Низ, Кор, Кардіо) та `getSubgroups` для рівнів 2–3. У стані зберігаються `selectedGroupLevel1`, `selectedGroupLevel2`, `selectedGroupLevel3` для фільтрації пошуку.
- **Пошук «Ввести назву»:** мінімум 3 символи; пошук за назвою та псевдонімами (`Alias.searchExercisesWithAliases`). Результати **тільки з обраної групи** (перетин з `getExercisesByGroup(level1, level2, level3)`). У повідомленні вказується група (наприклад «група: Низ → Спина»).

### 2.4 Вибір кількості підходів або кругів

- **Одиночна вправа:** після вибору однієї вправи показується екран «Скільки підходів виконаєте?» — кнопки 3, 4, 5. Значення зберігається в `plannedSetsCount`.
- **Сет:** після формування списку вправ (≥2) і натискання «Перейти до тренування» показується «Скільки кругів виконаєте?» — кнопки 3, 4, 5. Значення зберігається в `plannedRoundsCount`.

Константи: `TRAINING_PLANNED_SETS`, `TRAINING_PLANNED_ROUNDS`. Стан: `TRAINING_CHOOSE_SETS`.

### 2.5 Запис підходів

- **Одиночна вправа:** для кожного підходу (1 … plannedSetsCount) запитується вага і повтори. Кнопок «Додати підхід» немає. Після запису останнього підходу вправа автоматично вважається завершеною.
- **Сет:** кожен круг = послідовне виконання всіх вправ списку (по одному підходу на вправу). Після введення ваги/повторів для останньої вправи круга — автоматично перехід до наступного круга або завершення сету (якщо виконано plannedRoundsCount кругів). Кнопки «Додати круг» під час виконання немає.

Під час виконання вправи/сету кнопка **«Завершити тренування»** не показується. Вона з’являється на екрані **«Оберіть тип тренування»** після завершення вправи або сету (разом із «Одиночне» та «Сет»). Кнопки «Скасувати» на цьому екрані немає — лише «Завершити тренування».

### 2.6 Завершення та наступні кроки

- Після завершення вправи (одиночної) або сету показується екран «Оберіть тип тренування»: Одиночне, Сет, Завершити тренування.
- При «Завершити тренування» — фіксація слотів (якщо тренер вів учня), очищення стану, повернення в головне меню.

**Файли:** lib/training.js (askExecutionTypeThenMuscleGroup, showSetRoundsChoice, showSingleSetsChoice, askTrainingInputDataWithPlannedSets, askTrainingInputForSetCircuit, обробка TRAINING_PLANNED_SETS/ROUNDS, перевірка set circuit перед singleExecution, автозавершення за plannedSetsCount/plannedRoundsCount), lib/constants.js.

## 3. Тренування за планом (виконання плану учнем)

### 3.1 Вхід

- Учень: «Моє тренування» або тренер: «Тренування учнів» → учень з активним планом. Перевірка `active_plan_id` учня; план завантажується з `training_plan_exercises` по днях.

### 3.2 Вибір дня

- Показуються дні плану (День 1, День 2, …) з підписами (day_label з плану). Callback: `STUDENT_PLAN_DAY:dayNumber`.

### 3.3 Виконання вправ дня

- Для обраного дня виводиться список вправ з sets, reps, rest_sec. Користувач по черзі вводить вагу та повтори для кожного підходу кожної вправи. Кнопки: «Завершити вправу», «Завершити тренування».
- Записи йдуть у `bot_training_data` (chat_id учня, exercise_id, weight, reps, set).
- Після запису всіх підходів вправи за планом — автоматичний перехід до наступної вправи або завершення тренування.

### 3.4 Автопрогресія та деавтоматизація (після тренування)

- **Автопрогресія:** якщо учень виконав мінімум підходів і повторів — для наступного разу `target_weight` збільшується: базова вправа +2.5 кг, ізоляція +1.25 кг (за полем `vid` з exercise_library). Функція `applyProgressionAfterWorkout` у lib/training.js.
- **Деавтоматизація:** якщо учень двічі поспіль не виконав мінімум підходів у вправі — зменшення рекомендованої ваги на 10%, сповіщення тренеру. Динамічний текст без Markdown (VETO 6).

**Файли:** lib/training.js (startStudentPlanWorkout, showStudentPlanExercise, студентський ввід даних, finishStudentPlanWorkout, applyProgressionAfterWorkout), lib/supabase.js (getTrainingDataByChatAndDate, updatePlanExerciseTargetWeight).

## 4. Створення плану вручну

### 4.1 Вхід

- Тренер: Мої учні → [Учень] → Програма тренувань → «Новий план» → «Вручну».

### 4.2 Кроки створення

1. **Назва плану** — текст (мін. 2 символи). FSM: `PLAN_SET_NAME`.
2. **Ціль плану** — lose / gain / keep. Callback: `PLAN_GOAL`.
3. **Рівень складності не питається.** Рівень визначається автоматично з картки учня: `experience_start_date` → `getExperienceDays(user)` → `getLevelFromExperienceDays(days)` → beginner / intermediate / advanced. Зберігається в `planManualLevel`.
4. **Термін ревізії плану** — «За замовчуванням (N тиж.)» за рівнем (beginner 10, intermediate 7, advanced 5) або «Вказати тижнів» → вибір 4/6/8/10. Callback: `PLAN_REVISION_DEFAULT`, `PLAN_REVISION_INPUT`, `PLAN_REVISION_WEEKS`. Back веде до вибору цілі (`PLAN_REVISION_BACK`).
5. **Кількість тренувальних днів на тиждень** — 2, 3, 4 або 5. Callback: `PLAN_DAYS`.
6. **Акцент-зони** — вибір зон для акценту (toggle за ACCENT_ZONES_ORDER: glutes, legs, thighs, abs, arms, back, shoulders, full). Callback: `PLAN_ACCENT_TOGGLE`, далі «Далі» (`PLAN_ACCENT_NEXT`) або «Назад» (`PLAN_ACCENT_BACK`).
7. **Зони уникнення** — вибір зон для мінімізації або «Пропустити». Callback: `PLAN_AVOID_TOGGLE`, `PLAN_AVOID_SKIP`, `PLAN_AVOID_NEXT`, `PLAN_AVOID_BACK`.
8. **Превʼю спліту** — показ розподілу груп м'язів по днях (splitConfig). Кнопки «Підтвердити» (`PLAN_SPLIT_CONFIRM`) або «Назад» (`PLAN_SPLIT_BACK`). При підтвердженні — INSERT у `training_plans` з accent_zones, avoid_zones, split_config (splitScheme з getSplitSchemeAndDays або generateSplitWithAccent). План створюється без вправ; далі тренер може додати вправи через «Додати вправи» або активувати порожній.

### 4.3 Додавання вправ у план

- Відкритий план → «Додати вправи» → вибір дня (День 1, День 2, …; підписи днів з `plan.splitConfig`, якщо є) → вибір групи м'язів (рівень 1 з TOP_LEVEL_GROUPS, потім рівень 2 з GROUPS_BY_TOP або «Всі вправи тут»).
- **Градація по групі 3:** після вибору групи 2-го рівня, якщо в БД є підкатегорії (group_level3), показується екран підкатегорій 3-го рівня; можна обрати підкатегорію або «Всі вправи тут». Список вправ формується через `getExercisesByGroup(level1, level2, level3)`.
- Вибір вправи → **екран пресетів сетів** (PLAN_SETS_PRESET): варіанти sets/reps/rest за **ціллю плану** (goal) та **рівнем** (planManualLevel) з константи SET_PRESETS. Кнопки: пресет (PLAN_SETS_PRESET:key), «Свій варіант» (PLAN_SETS_CUSTOM), «Назад» (PLAN_SETS_BACK). Після вибору пресету або введення свого — збереження в `training_plan_exercises` (sets, reps, rest_sec). Можливий пошук за назвою (PLAN_SEARCH, мін. 3 символи, з урахуванням псевдонімів).

### 4.4 Перегляд плану та картки вправ

- У деталях плану (список днів і вправ) доступні: «Додати вправи», «Картки вправ» (якщо є вправи), «Активувати» / «Активний план», «Видалити», «До списку планів».
- **Картки вправ:** кнопка відкриває список вправ плану; кожна вправа — кнопка, що веде до картки вправи з бібліотеки (опис, відео, протипоказання). У картці при відкритті з плану показується «Назад до плану» замість «Назад до списку»; повернення веде до деталей плану. Callback: `PLAN_VIEW_EXERCISE`, `PLAN_BACK_TO_PLAN`.

**Файли:** lib/trainingPlan.js (askPlanName, askPlanGoal, askPlanRevisionWeeks, askPlanDays, showPlanEditDaySelect, showPlanEditTopGroups, showPlanEditSecondLevelGroups, showPlanEditThirdLevelGroups, showPlanEditExercises, showPlanDetail, showPlanExerciseCardsList), lib/constants.js, lib/library.js (showExerciseDetail з options.returnToPlan), lib/router.js.

## 5. Авто-план (авто-підбір)

### 5.1 Вхід

- Тренер: Мої учні → [Учень] → Програма тренувань → «Новий план» → «Авто-підбір».

### 5.2 Підсумок профілю та генерація

- Читання профілю учня з БД: goal, gender, weight, height, experience_start_date, training_days_per_week, активні записи з `user_medical_conditions`. Рівень визначається з experience_start_date (getExperienceDays → getLevelFromExperienceDays). Дні на тиждень — з профілю або дефолт за рівнем.
- Екран підсумку: ціль, рівень, тренувань на тиждень, опційно вибір кількості вправ на день (кнопки) або за рекомендацією. Кнопки: **«→ Далі до акценту»** (PLAN_ACCENT_START) — перехід до вибору акцент-зон, зон уникнення та превʼю спліту; **«⚙️ Генерувати»** (PLAN_GENERATE) — генерація без акцентів (звичайний getSplitSchemeAndDays). При «Далі до акценту» — послідовно: акцент-зони → зони уникнення (або пропуск) → превʼю спліту → «Підтвердити» → виклик `generateTrainingPlan(studentChatId, options)` з options.accentZones, options.avoidZones, options.splitConfig (з `generateSplitWithAccent`).

### 5.3 Алгоритм генерації (generateTrainingPlan)

1. **Профіль:** users (goal, gender, experience_start_date, training_days_per_week тощо), user_medical_conditions (is_active = true). Level = getLevelFromExperienceDays(getExperienceDays(user)). Days per week — з options або профілю, інакше дефолт за рівнем.
2. **Схема та дні:** якщо передано **options.splitConfig** (після превʼю спліту) — використовується він для формування dayConfigs; інакше getSplitSchemeAndDays(level, daysPerWeek, gender). При наявності accentZones/avoidZones викликається **generateSplitWithAccent(daysPerWeek, accentZones, avoidZones, gender, level)** для побудови splitConfig (розподіл груп по днях з урахуванням акцентів та уникнення). ACCENT_MAP у constants.js змаповує ключі зон на **group_level2** з exercise_library (7 груп: Спина, Груди, Плечі, Сідниці, Ноги, Прес, Руки).
3. **Для кожного дня:** визначення цільових груп м'язів (group_level2) за типом дня або з splitConfig. Вправи з exercise_library за цими групами, активні. filterExerciseForUser(exercise, userMedConditions) — виключення BLOCKED, пріоритет SAFE, позначка ALLOWED_WITH_MOD.
4. **Anti-Repeat:** правило А — одна вправа не повторюється в різних днях одного плану для тієї самої group_level2 (excludeExerciseIdsByGroup). Правило Б — ізоляційні вправи попереднього плану учня виключаються (getPreviousPlanIsolationExerciseIds). Правило В — зважений вибір для ізоляційних: вага = 1 / (usage_count + 1) (getExerciseUsageCountForStudent).
5. **Sets, reps, rest:** getSetsRepsRest(goal, level) — за ціллю та рівнем. Запис у training_plan_exercises з sets, reps, rest_sec, day_number, day_label, order_in_day, medical_status.
6. **Збереження:** insertTrainingPlan (plan_name, goal, level, days_per_week, revision_weeks за рівнем, parent_plan_id опційно, **accent_zones**, **avoid_zones**, **split_config**), потім INSERT вправ у training_plan_exercises.

### 5.4 Після генерації

- Показ згенерованого плану (дні та вправи). Кнопки: «Редагувати» (перехід до додавання/редагування вправ), «Активувати», «Видалити». При активації — setPlanActiveForStudent (is_active = true для цього плану, false для інших; valid_until = now + revision_weeks * 7 днів; activated_at = now).

**Файли:** lib/planGenerator.js (generateTrainingPlan, getSplitSchemeAndDays, getSetsRepsRest, pickExercisesForDay, weightedSample, filterExerciseForUser через medicalFilter), lib/supabase.js (getPlanExerciseIdsWithVid, getPreviousPlanIsolationExerciseIds, getExerciseUsageCountForStudent, insertTrainingPlan, setPlanActiveForStudent), lib/trainingPlan.js (showAutoSummary, обробка PLAN_GENERATE).

## 6. Медична фільтрація та рівні

### 6.1 filterExerciseForUser

- Вхід: вправа (з exercise_library), масив активних user_medical_conditions. Вихід: BLOCKED | ALLOWED_WITH_MOD | SAFE | NEUTRAL. BLOCKED — виключити з плану; ALLOWED_WITH_MOD — включити з поміткою/модифікацією; SAFE — пріоритизувати; NEUTRAL — стандартний відбір.
- Джерело правил: medical_contraindications, medical_limitations, safe_for у вправі; порівняння severity з порогами.

### 6.2 Рівень (level)

- Визначення: experience_days від experience_start_date (днів від початку досвіду). 0–90 → beginner, 91–365 → intermediate, 366+ → advanced. Функції: getExperienceDays(user), getLevelFromExperienceDays(days) у lib/planGenerator.js.

### 6.3 Термін ревізії (revision_weeks)

- За замовчуванням за рівнем: beginner 10 тиж., intermediate 7 тиж., advanced 5 тиж. Константа REVISION_WEEKS_BY_LEVEL у lib/supabase.js. При активації плану: valid_until = activated_at + revision_weeks * 7 днів.

### 6.4 Акцент-зони та ACCENT_MAP

- Ключі зон: glutes, legs, thighs, abs, arms, back, shoulders, full. **ACCENT_MAP** (lib/constants.js) змаповує кожен ключ на масив значень **group_level2** з exercise_library. Використовуються лише **7 груп**, що реально є в бібліотеці: Спина, Груди, Плечі, Сідниці, Ноги, Прес, Руки (thighs → Ноги+Сідниці, full → порожній масив). Це забезпечує коректний підбір вправ при generateSplitWithAccent та генерації плану.

## 7. Ревізія плану та нагадування

- Cron GET /cron/plan-revision: getPlansDueForRevision() — плани з valid_until &lt; now і revision_reminder_sent_at IS NULL. Тренеру надсилається нагадування «Час оновити план для [Ім'я]», позначка revision_reminder_sent_at.
- Авто-ревізія (generatePlanRevision) та запис у plan_adjustments — у майбутніх версіях; зараз ревізія — ручна (нагадування тренеру).

**Файли:** lib/planRevisionReminders.js, lib/supabase.js (getPlansDueForRevision, markPlanRevisionReminderSent).

Нижче — рекомендації щодо документів, **пов’язаних із планом тренувань та записами тренувань**, після появи цього консолідованого опису.

### Можна видалити без втрати логіки

| Документ | Причина |
|----------|--------|
| **Логіка складання плану тренувань OLD не использовать.md** | Позначено як застарілий; логіка перенесена в v1.1 та в цей документ. |

### Можна архівувати або видалити після перевірки

| Документ | Рекомендація |
|----------|--------------|
| **План_тренувань_зміни_2_2_та_3_5_3_9.md** | Пропозиції змін (getSetsRepsRest, revision_weeks у UI тощо). Якщо відповідні пункти вже впроваджені — файл можна архівувати (наприклад у папку `archive/`) або видалити. Логіка змін описана в цьому документі та в «Зміни_логіки_та_функціоналу.md». |

### Краще залишити (різне призначення)

| Документ | Причина |
|----------|--------|
| **Логіка_складання_плану_тренувань_v1_1.md** | Детальні алгоритми (медичні коди, таблиці, псевдокод, БД). Цей документ — «Логіка тренувань та планів» — описує потоки та сценарії; Логіка v1.1 залишається джерелом для формул, MC-кодів, Anti-Repeat тощо. Можна згодом посилатися з цього документа на конкретні розділи v1.1 замість дублювання. |
| **Технічне завдання Модуль _План тренувань_.md** | Технічна специфікація: SQL-міграції, FSM, модулі, VETO. Не замінюється описом бізнес-логіки. |
| **План_тренувань_звірка_з_ТЗ_та_Логікою.md** | Звірка «що реалізовано / протиріччя / що впровадити». Корисна для розробки та аудиту; доповнює цей документ, а не дублює його. |
| **Зміни_логіки_та_функціоналу.md** | Хронологія змін логіки та функціоналу по всьому проекту. Продовжувати доповнювати при змінах; не видаляти. |
| **Бізнес-логіка_Gym_3_0_v1.1.md** | Загальна бізнес-логіка та статус реалізації по продукту. Залишити; у ньому можна додати посилання на «Логіка_тренувань_та_планів.md» для деталей по тренуваннях і планах. |

**Підсумок:** безпечно видалити один файл — **«Логіка складання плану тренувань OLD не использовать.md»**. Решту документів доцільно зберегти; при бажанні можна архівувати **План_тренувань_зміни_2_2_та_3_5_3_9.md**, якщо всі описані там зміни вже зроблені.
